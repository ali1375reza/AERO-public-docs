# رخدادها، خطاها، اصلاح‌ها و درس‌ها

در AERO خطا بخشی از شواهد سیستم است. سابقهٔ عمومی، رخداد، اثر، اصلاح و عدم‌قطعیت باقی‌مانده را نگه می‌دارد.

| رخداد | اثر | اصلاح یا درس عمومی |
|---|---|---|
| فیلترهای بیش‌ازحد سخت | تقریباً هیچ فرصتی باقی نمی‌ماند | محل حذف کاندیدا اندازه‌گیری شود؛ فیلتر بیشتر الزاماً کیفیت بیشتر نیست. |
| فیلترهای بیش‌ازحد باز | فعالیت بیشتر اما اقتصاد منفی | حسابداری کامل هزینه و ریسک برگردد؛ تعداد معامله Edge نیست. |
| خطای تعریف Event در Replay | تعداد تصمیم مصنوعی زیاد شد | Snapshot کامل پیش از تصمیم Batch شود. |
| ناقص‌بودن P&L LP | بخشی از اقتصاد اجرا دیده نشد | مدل به ابزار پژوهش/رد تبدیل شود، نه مجوز Live. |
| Drift ساعت و خطر State قدیمی | کنترل زمان آلوده می‌شد | Timestamp معتبر و Freshness Guard صریح استفاده شود. |
| Timeout و Rate Limit RPC عمومی | تست‌های سرعت متوقف یا کند شدند | خطای انتقال از `NO_EDGE` جدا و Fallback/Retry محدود اضافه شود. |
| تمام‌شدن سهمیهٔ Provider | Shadow طولانی پس از Refreshهای ناموفق متوقف شد | Fail-closed؛ هرگز با Coverage قدیمی ادامه داده نشود. |
| ناسازگاری WebSocket | Endpoint رایگان کانال لازم را نداد | پشتیبانی Protocol واقعاً تست شود؛ Polling از Event جدا باشد. |
| Tierهای ثابت پوشش | موقعیت نزدیک به مرز از اولویت خارج می‌شد | Universe کامل دیده شود و ظرفیت اولویت تطبیقی باشد. |
| Pending Hash صفر | Context Proof قبلی ناامن شد | Hash فقط Telemetry باشد و Reconfirmation مستقل لازم شود. |
| Busy-Skip هنگام بار Event | یک Worker داغ عقب می‌ماند | Concurrency بر اساس Telemetry تنظیم و Gate دوباره اجرا شود. |
| فشار Disk و Swap | آمادگی عملیاتی پایین آمد | Storage و Retention بخشی از Readiness تلقی شود. |
| ناسازگاری Dependency محیط اجرا | Runner پیش از Validation متوقف شد | Provenance محیط ثبت و Runtime معتبر استفاده شود. |
| برخورد Output و Provenance | Candidate جدید ممکن بود شبیه Evidence قدیمی دیده شود | هویت Source/Evidence Freeze و خروجی هر Run جدا شود. |
| تفسیر Stop Reason پیش‌فرض به‌عنوان پایان | خطر PASS جعلی | Endpoint واقعی، Evidence تازه و Gate سه‌حالته لازم است. |
| اشتباه Health و Liquidatable | Route برای موقعیت واجدشرایط‌نبودن باز می‌شد | State معتبر پیش از Route تطبیق داده شود. |
| اختلاف ارزش‌گذاری Oracle | Probe به Validation پروتکل رسید اما رد شد | Semantics قیمت و State تاریخی بررسی شود. |
| خطای واحد Health Factor | رتبه‌بندی اولیه مقیاس غیرواقعی داشت | خروجی مقدماتی اعلام، نرمال‌سازی اصلاح و Validation تکرار شود. |
| رد Route یا Calldata | Capture اجرایی اثبات نشد | شکست حفظ و Route تا اثبات قرارداد ورودی/State مسدود بماند. |

## درس‌های کلی

۱. Correctness یک زنجیره است: Discovery، State، Freshness، Economics و Execution باید هم‌راستا باشند.
۲. خطای Provider نتیجهٔ اقتصادی نیست.
۳. موفقیت تاریخی یا Fork سود زنده نیست.
۴. فرصت مشاهده‌نشده باید `NOT_OBSERVED` ثبت شود.
۵. هویت Evidence و سلامت Storage بخشی از مهندسی‌اند.
